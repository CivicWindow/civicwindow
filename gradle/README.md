# Gradle inputs

**Status:** Proposed. The catalog and the wrapper settings are written, but no build has run, so none of them is claimed to work yet. The first run is the first CI run after the repository is published.

## What is here

| file | what it holds |
|---|---|
| [`libs.versions.toml`](libs.versions.toml) | The version catalog: every dependency and plugin version, written once (see [ADR-0007](../docs/adr/0007-module-and-build-structure.md)). |
| [`wrapper/gradle-wrapper.properties`](wrapper/gradle-wrapper.properties) | The Gradle version for everyone: 9.6.0, the `bin` distribution, its sha256 and the address check (see [ADR-0002](../docs/adr/0002-build-toolchain.md)). |

Every version is checked again at the first build. The convention plugins that read the catalog are in [build-logic](../build-logic/README.md); the role builds are in [role-configs](../role-configs/README.md).

## Not made yet

These files are generated by Gradle and never written by hand. None exists yet:

- `gradlew`, `gradlew.bat` and `gradle/wrapper/gradle-wrapper.jar`, made by the wrapper task;
- `gradle/verification-metadata.xml`, made by Gradle's dependency verification option;
- the dependency lock files, made by Gradle's write-locks option.

Until they exist the tree has no wrapper script, so it cannot be built.

## First-run command (not yet run)

Run once from the repository root, with a Gradle installed on the machine. It makes the three wrapper files and writes the wrapper settings from the same values as `wrapper/gradle-wrapper.properties`:

```text
gradle wrapper --gradle-version 9.6.0 --distribution-type bin --gradle-distribution-sha256-sum bbaeb2fef8710818cf0e261201dab964c572f92b942812df0c3620d62a529a01
```

Afterwards `gradlew` and `gradlew.bat` replace the installed Gradle. The command is marked "not yet run" until a first run shows its output.

The [development environment guide](../docs/operations/DEV_ENVIRONMENT.md#first-run-the-gradle-wrapper) gives the command that writes the verification metadata, which is open for Gradle 9.6.0, and names Gradle's write-locks option without a command for the lock files. Neither has run yet.

## Failure behavior

- The wrapper refuses a distribution whose sha256 differs from `distributionSha256Sum`, and validates the distribution address.
- Gradle fails the build on a plugin or library alias that the catalog does not declare.
- A version is changed in `libs.versions.toml` only; the Gradle version is changed only by running the command above again with the new version and its published sha256.

Standards: Gradle documentation on the [Gradle Wrapper](https://docs.gradle.org/current/userguide/gradle_wrapper.html), [version catalogs](https://docs.gradle.org/current/userguide/version_catalogs.html), [dependency verification](https://docs.gradle.org/current/userguide/dependency_verification.html) and [dependency locking](https://docs.gradle.org/current/userguide/dependency_locking.html); the sha256 is the one Gradle publishes on its [release checksums](https://gradle.org/release-checksums/) page.

Enforcement: the wrapper checks the distribution's sha256 and address on every download; review is the check that the command above equals `wrapper/gradle-wrapper.properties` until the first CI run.
